# Rishe Store

فروشگاه مستقل ریشه و پنل عملیاتی یکپارچه برند، بازطراحی‌شده با Next.js و PostgreSQL و مستقر روی `new.rishe.store`.

## معماری

- Next.js App Router
- PostgreSQL + Prisma
- احراز هویت اختصاصی با Cookie امن و Role/Capability برای تیم
- فروشگاه، دسته‌بندی، محصول، پک، سبد خرید و Checkout
- حساب مشتری، تاریخچه و پیگیری سفارش
- قیمت و موجودی واقعی منتقل‌شده از کاتالوگ قبلی
- رزرو موجودی، Promotion و Loyalty
- پنل مدیریت محصولات، سفارش‌ها، محتوا، تصاویر و تنظیمات
- ERP عملیاتی شامل انبار، Batch، گردش موجودی، تامین، خرید، تولید، حسابداری، خزانه، B2B، امانی، لجستیک، مالیات و Analytics
- Event POS با دستگاه‌های مجاز، صف فروش آفلاین و Sync بعد از اتصال
- پرداخت Zibal با Verify سمت سرور
- اتصال Bale و Worker/Queue برای عملیات پس‌زمینه
- FAQ، مجله، Sitemap، Robots و Structured Data
- Docker Compose + PostgreSQL + Caddy HTTPS
- دیپلوی خودکار با GitHub Actions روی new.rishe.store

## اولین راه‌اندازی

بعد از اولین Deploy، به این آدرس برو:

https://new.rishe.store/setup

در اولین راه‌اندازی مدیر اصلی و تنظیمات پایه فروشگاه ساخته می‌شوند. بعد از ایجاد مدیر، صفحه Setup بسته می‌شود.

کاتالوگ ریشه از داده‌های فروشگاه قبلی Seed می‌شود و Snapshot قیمت و موجودی واقعی نیز در Seed ثبت شده است. بعد از آن، تغییرات قیمت، موجودی، عکس و محتوا از پنل مدیریت انجام می‌شود و Seed تغییرات مدیریتی بعدی را بازنویسی نمی‌کند.

## Secrets لازم برای Deploy

در GitHub Actions:

- HOST
- PASS
- SSH_USER اختیاری
- ZIBAL_MERCHANT
- BALE_BOT_TOKEN اختیاری
- BALE_ADMIN_CHAT_ID اختیاری
- BALE_WEBHOOK_SECRET اختیاری
- TAX_SUBMIT_ENDPOINT اختیاری
- TAX_API_TOKEN اختیاری

DNS دامنه `new.rishe.store` باید مستقیماً به سرور اشاره کند. Caddy روی سرور HTTPS را مدیریت می‌کند.

## پرداخت

پرداخت آنلاین با Zibal انجام می‌شود. مبلغ سفارش فقط از دیتابیس سمت سرور گرفته می‌شود، Callback با Track ID سفارش تطبیق داده می‌شود و Verify نهایی سمت سرور انجام می‌شود. بعد از پرداخت موفق، رزرو موجودی قطعی می‌شود، وضعیت سفارش تغییر می‌کند، Loyalty و Promotion ثبت می‌شوند و تراکنش خزانه ایجاد می‌شود.

## Event POS

مدیر می‌تواند برای هر ایونت دستگاه POS مستقل با Token یک‌بارنمایش ایجاد کند. دستگاه بعد از ورود Session امن دریافت می‌کند. فروش‌های ثبت‌شده در زمان قطع اینترنت روی دستگاه در صف محلی باقی می‌مانند و پس از اتصال با Client UUID یکتا Sync می‌شوند تا فروش تکراری ثبت نشود.
